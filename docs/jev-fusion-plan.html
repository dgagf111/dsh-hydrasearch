把 Jev 的判断层融进 hydrasearch 的检索链

jev-search 的做法是「判断与检索彻底分离」：Jev 只回答结构化问题，从不生成查询词、从不生成答案， 两次判断夹一段并发检索，剩下全是确定性代码。能搬到本仓库，但只能搬进「检索之内」—— ctx.web 只给了一个 query 入参和一个 sources[] 出参，所以流式、分数、交互三件产品级特性无处安放。

2收窄点：seam 到底允许多少

provider 契约窄得超出直觉。这就是为什么 A 列的八个阶段到 C 列只剩五步， 以及为什么三件产品级特性必须在第 3 节里明说放弃。

入口 · WebSearchRequest

interface WebSearchRequest {
  readonly query: string
  readonly maxResults?: number
}

没有时间、没有源、没有站点、没有语言。所有 scoping 只能由代码或 Jev 在 provider 内部决定， 模型无法传参。想限定时间窗的唯一途径是把限定词写进 query 文本。

出口 · WebSearchSource

interface WebSearchSource {
  readonly url: string
  readonly title?: string
  readonly snippet?: string
  readonly publishedAt?: string   // ISO-8601
}
// 外层还有 content?: string（自由文本）
// 和 truncated: boolean（由 seam 设置）

没有分数字段。Jev 算出的 0..1 切题度，唯一的归宿是 sources[] 的数组顺序。 content 是唯一的自由文本通道。

jev-search 的产物在 seam 里的归宿结论
intent / found / lane 事件 无流式通道 —— search() 只是一个 Promise，中途没有回调面 ✗ 只能挤进 content 文本
relevance 0..1 WebSearchSource 没有分数字段 ⚠ 降级为数组顺序
Best / Newest 切换、可编辑 chip 没有 UI 面；provider 是 Host 侧代码 ✗ 降级为配置项
window（24h / 7d / 30d） TinyFish 有 after_date / recency_minutes；AnySearch 无任何时间过滤 ⚠ 只能单边生效
12 个源的 source_* noul AnySearch 有 40 个 sub-domain，其中约 7 类是真 vertical；HN / YouTube / Wikipedia / 新闻只能走 general ⚠ 源集合缩水
每 lane 独立失败 provider 内部即可实现，seam 不关心 ✓ 无损
cache.ts 的 KV 缓存 ctx.storage 的 KvFacet，或进程内 Map ✓ 无损

凭据：新增 HYDRASEARCH_TYPESAFE_API_KEY， 沿用既有约定 —— 引用名不能与常见环境变量同名，否则会被环境变量永久遮蔽且写不进去 （见 lib/tinyfish.js:38-53）。 没有 key 时自动视为不可用，退回纯检索链。

卡片侧：字段表是数据驱动的，但 BACKENDS 硬编码为两个后端。判题不是第三个 backend，所以不塞进那张表 —— 在顶层加一小块「判题」区域即可。

诚实性四条降级路径，沿用既有规则

1 没有 Jev key记 skipped-unavailable（「没试」），不是 failed（「试了并失败」）。搜索结果与今天逐字节一致。 关闭
2 Jev 调用失败退回原 query / 未排序结果，在 content 里写「judging unavailable: 原因」。整条搜索仍然成功。 降级
3 用户取消abort 直接抛 WEB_ABORTED —— 不换供应商、不换后端。与 lib/index.js:1105 同一条规则。 穿透
4 Jev 只换值得换的错误402 / 429 / 5xx 才换供应商；400 / 401 / 422 不换（重试也是白重试）。 选择
